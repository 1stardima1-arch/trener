# Тренер — ИИ-тренер для атлетов

Приложение уровня Whoop: готовность к тренировкам, план на сегодня, сон и питание —
всё строится ИИ-тренером на основе твоих реальных данных. Лактатные пороги, порог ЧСС
и VO2max определяются автоматически по данным устройств, независимо от их модели.
Каждое решение — от оценки восстановления до изменения плана — можно раскрыть и увидеть,
почему оно именно такое.

**Стек:** Next.js 16 (App Router) · TypeScript · Tailwind CSS v4 · Prisma + PostgreSQL ·
Auth.js v5 · Groq (бесплатный быстрый ИИ) · Recharts · Framer Motion.

---

## 0. Как это всё устроено (коротко)

- **`src/lib/physiology/*`** — сама «наука»: определение лактатных порогов (методы
  Dmax/Modified Dmax/OBLA), зон ЧСС/темпа/мощности, оценка VO2max (ансамбль из нескольких
  независимых формул: по результату старта — VDOT Дэниелса-Гилберта, по порогу LT2 —
  уравнения ACSM, по ЧСС макс/покоя — Uth et al., без теста — регрессия Jackson et al.),
  тренировочная нагрузка (TRIMP Банистера, CTL/ATL/TSB, ACWR), оценка готовности (HRV/RHR
  относительно твоей собственной скользящей нормы — методология Plews/Buchheit), питание
  (TDEE по Mifflin-St Jeor/Katch-McArdle, периодизация углеводов по Burke et al.) и генератор
  адаптивного плана тренировок (периодизация база→развитие→пик→снижение нагрузки, принцип
  80/20, правило 3:1 недель), а также детектор аномалий: одновременный рост пульса покоя и
  падение ВСР — риск болезни/недовосстановления; отрицательная форма (TSB) + высокий ACWR +
  устойчивое снижение ВСР несколько дней подряд — риск перетренированности; устойчивый рост
  ВСР со снижением пульса покоя — реальный прогресс формы. Всё — чистые функции, без
  обращений к базе, с понятным объяснением на выходе.
- **`src/lib/engine.ts`** — связывает эти формулы с базой: пересчитывает пороги,
  готовность и план при каждой синхронизации устройства, загрузке .fit-файла или
  ручной записи, пишет в ленту «Почему» понятную причину каждого изменения и один раз в
  день формирует «Слово тренера» — короткий проактивный брифинг на главном экране,
  который сводит воедино готовность, сон, план и любые тревожные флаги.
- **`src/lib/integrations/*`** — реальные клиенты Polar AccessLink, Athyx REST API,
  разбор .fit-файлов и неофициальная синхронизация с Garmin (подробности ниже).
- **`src/lib/ai.ts`** — ИИ-тренер (Groq): отвечает на вопросы и «очеловечивает» уже
  вычисленную причину решения — сама причина всегда сначала считается по формуле, ИИ её
  не выдумывает, только объясняет по-человечески.

Это не заявление «мы обучили ИИ с нуля» — модель (Groq/Llama) уже обучена; то, что
«обучено» здесь — это сама система формул и правил, которые решают, что показать
атлету и почему, а модель лишь озвучивает уже принятое решение понятным языком.

## 1. Быстрый старт (локально)

```bash
npm install
cp .env.example .env
```

Обязательный минимум в `.env`:

```bash
DATABASE_URL="postgresql://user:password@localhost:5432/trener"
AUTH_SECRET="сгенерируй: openssl rand -base64 33"
APP_ENCRYPTION_KEY="сгенерируй: openssl rand -base64 32"
NEXTAUTH_URL="http://localhost:3000"
```

Примени схему БД:

```bash
npm run db:push
```

Запусти:

```bash
npm run dev
```

Открой [http://localhost:3000](http://localhost:3000), зарегистрируйся по нику+паролю —
дальше открой профиль настройки (онбординг). Без `GROQ_API_KEY` всё работает, кроме
ответов ИИ-тренера (см. ниже — 2 минуты, бесплатно).

---

## 2. База данных (Postgres)

Нужен адрес подключения (`DATABASE_URL`):

- **[Neon](https://neon.tech)** — бесплатный тариф, готовая строка `postgresql://...`.
- **[Supabase](https://supabase.com)** → Project Settings → Database → Connection string.

`npm run db:push` применит `prisma/schema.prisma` к базе.

---

## 3. ИИ-тренер — Groq (бесплатно и быстро)

1. **[console.groq.com/keys](https://console.groq.com/keys)** → Create API Key.
2. В `.env`: `GROQ_API_KEY="твой_ключ"`.
3. Перезапусти `npm run dev`.

Без ключа приложение работает полностью — только чат с ИИ-тренером и «очеловеченные»
объяснения в ленте «Почему» отвечают заглушкой/сухим текстом вместо тёплого объяснения.

## 4. Синхронизация устройств — что реально работает и как

### Athyx (лактат) — официальный API, работает "из коробки"

У Athyx есть настоящий REST API для разработчиков (`api.athyx.com/v1`, ключ вида
`ath_live_…`). Атлет создаёт ключ на **[athyx.com/developers](https://www.athyx.com/developers)**
в своём аккаунте и вставляет его на странице «Устройства» в приложении — никаких
переменных окружения на сервере не требуется. Подтягиваются сессии, лактатные зоны и
метаболическая нагрузка.

### Polar — официальный OAuth2 (AccessLink), самостоятельная бесплатная регистрация

1. Зайди на **[admin.polaraccesslink.com](https://admin.polaraccesslink.com)** с любым
   аккаунтом Polar Flow (устройство Polar не нужно) и зарегистрируй приложение —
   бесплатно, без компании/железа, в отличие от Garmin.
2. Redirect URI: `<твой домен>/api/devices/polar/callback`.
3. В `.env`: `POLAR_CLIENT_ID` и `POLAR_CLIENT_SECRET`.
4. На странице «Устройства» атлет жмёт «Подключить через Polar Flow» — дальше обычный
   OAuth2-флоу. Синхронизация — по модели транзакций AccessLink (открыть транзакцию →
   получить новые тренировки → подтвердить), плюс сон и Nightly Recharge.
5. Опционально — вебхук для мгновенной синхронизации вместо ожидания опроса: зарегистрируй
   `<домен>/api/devices/polar/webhook` в том же кабинете и добавь
   `POLAR_WEBHOOK_SIGNATURE_SECRET` в `.env`.

### Garmin — открытый разбор .fit (работает всегда) + неофициальная синхронизация (опционально)

Официальный **Garmin Connect Developer Program** сейчас (2026) закрыт для новых заявок —
форма подачи заявки снята с сайта Garmin без объявленной даты возврата. Поэтому:

- **Разбор .fit-файлов работает без каких-либо ключей**, для Garmin, Polar, Suunto, Wahoo
  и любых других устройств — это официальный открытый Garmin FIT SDK
  (пакет `@garmin/fitsdk`, MIT-лицензия), а не закрытый Connect API. Экспортируй
  «Original» из Garmin Connect (Settings → Export), или Polar Flow → Export, или скопируй
  файл с устройства по USB из папки `/GARMIN/ACTIVITY`, и загрузи на странице «Тренировки».
- **Неофициальная синхронизация** — тот же способ входа, что используют открытые проекты
  на GitHub (`python-garminconnect`, `garth`, `garmin-connect`): вход по логину/паролю
  Garmin Connect через их же SSO, обмен на OAuth1-, затем OAuth2-токен. Пароль нигде не
  сохраняется — только результирующий токен, зашифрованный в базе. Выключено по умолчанию
  (`ENABLE_GARMIN_UNOFFICIAL_SYNC="false"`), включается осознанно самим атлетом на странице
  «Устройства» — это не официальный API и технически не соответствует условиям
  использования Garmin Connect, как и все аналогичные open-source клиенты.
  `GARMIN_CONSUMER_KEY`/`GARMIN_CONSUMER_SECRET` — те же значения, что используют
  перечисленные выше открытые проекты (посмотри в их исходниках); они периодически
  меняются Garmin, поэтому не зашиты в код напрямую.

### Другие лактометры и любые устройства без API

Ручной ввод — на странице «Устройства» (разовое измерение) и «Тренировки» (полный
степ-тест из нескольких ступеней «пульс + лактат» — по нему считаются пороги тем же
методом Dmax, что и для Athyx).

## 5. Автоматический ежедневный пересчёт (Vercel Cron)

`vercel.json` уже содержит cron на `/api/cron/daily-recompute` (каждый день в 04:00 UTC) —
подтягивает новые данные с подключённых устройств, пересчитывает готовность и, если
нужно, адаптирует план на сегодня для всех атлетов. Добавь `CRON_SECRET` в `.env`/Vercel
(Vercel сам подставит его в заголовок запроса) — без него эндпоинт тоже работает, но без
проверки, что вызов пришёл от настоящего Vercel Cron.

---

## 6. Вход и восстановление пароля

Работает так же, как в предыдущих версиях этого стека: почта (magic-link через Resend),
ник+пароль (bcrypt), восстановление пароля по одноразовой ссылке, вход по отпечатку/Face ID
(WebAuthn/passkeys, настоящий стандарт). Настройка Resend/админа — переменные
`RESEND_API_KEY`, `ADMIN_EMAILS`/`ADMIN_USERNAME`+`ADMIN_PASSWORD` в `.env` (подробности —
в комментариях `.env.example`). Админ-аккаунт создаётся автоматически при каждом деплое
(`prisma/seed.ts`).

## 7. Деплой в продакшен

**[Vercel](https://vercel.com)**:

1. Импортируй репозиторий.
2. Добавь все переменные из `.env` (продакшен `DATABASE_URL`, реальный `NEXTAUTH_URL`).
3. После первого деплоя один раз выполни `npm run db:push` с продакшен `DATABASE_URL`.

## 8. Android-приложение (APK) через GitHub Actions

Та же схема TWA (Trusted Web Activity), что и раньше — секреты подписи
(`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`) уже должны
быть в **Settings → Secrets and variables → Actions**, если они настраивались раньше в
этом репозитории. **Важно:** это отдельное приложение с новым Android-идентификатором
(`ru.trener.app` вместо `ru.ball.app` у предыдущей версии) — тот же ключ подписи можно
переиспользовать (ключ не привязан к package id), но это осознанно новый, независимый
Android-пакет, а не обновление предыдущего.

Actions → **«Build Android APK (TWA)»** → Run workflow → скачай `trener-app-apk` из
Artifacts. Если домен деплоя не `trener-coach.vercel.app` — обнови `webManifestUrl` при
запуске workflow и `package_name` в `public/.well-known/assetlinks.json`.

## 9. Структура проекта

```
prisma/schema.prisma          — модели БД (профиль атлета, устройства, активности,
                                 лактат, пороги, дневные метрики, план, питание, соцфункции)

src/lib/physiology/            — пороги, зоны, VO2max, тренировочная нагрузка,
                                  восстановление, питание, генератор плана (чистые функции)
src/lib/integrations/          — FIT-парсер, клиенты Polar/Athyx/Garmin
src/lib/engine.ts              — оркестрация: формулы + БД + лента «Почему»
src/lib/ai.ts                  — ИИ-тренер (Groq)
src/lib/actions/               — server actions (онбординг, профиль, устройства,
                                  ручной ввод, питание, соцфункции)

src/app/(marketing)/, src/app/page.tsx — лендинг
src/app/login/                 — вход/регистрация
src/app/app/*                  — приложение: дашборд, тренировки, сон, питание,
                                  устройства, лента, ИИ-тренер, профиль, админка
src/app/api/devices/*          — OAuth2/вебхуки Polar
src/app/api/coach/chat         — стриминговый чат с ИИ-тренером
src/app/api/cron/daily-recompute — ежедневный пересчёт (Vercel Cron)
```

## 11. Честно о границах

- Рекомендации ИИ-тренера и оценки готовности — не медицинская консультация; при травмах
  или симптомах болезни нужно обращаться к врачу (см. `/terms`, `/privacy`).
- Формулы восстановления/пороговых значений — реальные, опубликованные методики
  спортивной науки (см. комментарии в `src/lib/physiology/*` с указанием источников), но
  это не гарантия абсолютной точности — как и у любого носимого устройства, точность растёт
  по мере накопления данных о конкретном атлете.
- Неофициальная синхронизация с Garmin может сломаться в любой момент, если Garmin
  изменит страницу входа — это открытый риск, который несёт любой аналогичный проект на
  GitHub, а не что-то специфичное для этого приложения.
